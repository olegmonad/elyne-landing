План реализации Elyne — мастер-документ

Собрано 24.06.2026 перед стартом стройки. Сводит в одно: стратегию фаз, технический план вертикального среза, путь клиента и текущий статус. Это рабочая спина — по ней строим. Канон лежит в приватном репо, здесь — срез на момент старта.

0. Что строим (в одном предложении)

Агент, который из живого разговора понимает про человека то, что он сам ещё не сформулировал, и тут же начинает это делать руками. Не «ИИ-ассистент», а проводник: сначала зеркало («вот куда тебя тянет»), потом воплощение («а вот первый шаг — я его уже сделал»).

Главный KPI всего продукта. Тестер сам, непрошено, говорит: «это про меня — и оно реально что-то сделало». Не «похоже на чат». Всё остальное (БД, инфраструктура, экраны) — служебное; проверяем именно это ощущение.

1. Архитектура v4 — три слоя

  • Зеркало (кто я): диалог → портрет → рождение вектора.
  • Путь (куда иду): вектор → этап → шаг.
  • Воплощение / Реализатор (как создаю): автономный агент берёт участок пути и реально исполняет.

Канон цепочки (согласован с Сергеем — три сущности, не схлопывать):

Диалог → Паттерн → Named Insight («да, это про меня»)
       → Мотив («что мне на самом деле важно»)
       → Вектор («куда это ведёт»)
       → Путь → Действие → Результат → Feedback
  • Insight — не пересказ слов человека, а интерпретация/гипотеза, набравшая достаточно опор, чтобы стать осознанием.
  • Мотив — то скрытое, что инсайт открыл.
  • Вектор — направление разворачивания мотива, на уровень выше инсайта.

Спираль, а не конвейер (правка Сергея). Самопознание не заканчивается, когда начинается действие — оно продолжается ВНУТРИ действия. Как реально пошло дело, что человек выбрал / отбросил / где застрял → новые данные о нём → портрет уточняется → следующая задача точнее. Поэтому портрет никогда не «готов» — он живёт и углубляется через дело. Это и есть ров: мы дальше человека не потому что много спросили, а потому что видим траекторию его выборов в деле. (Полную спираль строим не сейчас — см. дисциплину минимализма.)

2. Путь клиента (спина, на которую всё ложится)

Шаг Что происходит
0. Привлечение Крючок — не «ИИ», а состояние: «узнать о себе то, что сам не сформулировал — и сразу начать это делать».
1. Рамка входа «За 15 минут покажу, куда тебя тянет — и помогу сделать первый шаг.» Не анкета, не тест.
2. Один живой запрос Вместо широкого самоопределения — одна актуальная вещь: «куда сейчас идёт энергия / какую задачу решаешь».
3. Микро-WOW реализацией ⟵ ПЕРВЫЙ ПЕРЕЛОМ Агент СРАЗУ делает маленькую реальную вещь. Вот чем мы не ChatGPT: он отвечает — наш делает.
4. Named insight вшивкой По ходу работы агент возвращает ОДИН точный инсайт про человека. Понимание через дело, не через анкету. Тут живёт ров.
5. Сферы разворачиваются От запроса агент мапит в сферу жизни, мягко показывает связи с другими — всегда «чтобы сделать для тебя больше».
6. Чекпоинт WOW ⟵ ТОЧКА КОНВЕРСИИ Критерий: инсайт сел + человек присвоил следующий шаг + что-то уже начал/делегировал.
7. Образ как бонус (опц.) Только когда якорей достаточно. Образ — приманка/закрепление, не продукт.
8. Переход «в работу» Персональный агент забирает делегируемые задачи, исполняет, трекает. Хэндофф портрет → спека → агент.
9. Петля удержания Два режима (Зеркало ↔ Воплощение). Портрет углубляется со временем. Чем дольше — тем ценнее.

Где рвётся (за чем следить): - Шаг 3 технически зависит от реализатора (мост OpenClaw). Пока не готов — путь обрывается на «понимании», и мы = «консультационное приложение, которое рынку не нужно». - Шаг 6 — если WOW не настоящий (эффект Барнума), конверсии нет. - Шаг 2 — если человек пришёл без запроса, путь не стартует; для фокус-группы фильтровать на «есть ли сейчас затык».

3. Главный принцип реализации: тонкий вертикальный срез

Олег нарисовал весь собор (инсайт → вектор → мультиагентная команда из скиллбокса → манифест-параметры → самообучение вкусу → виток спирали → мега-инсайты между сферами → ядро). Если строить целиком — не выкатим никогда.

Правило: строим тонкую сквозную ниточку через все три слоя на одном живом тестере, потом наслаиваем богатство.

человек говорит → 1 инсайт → 1 вектор → 1 этап → 1 действие
                → реализатор делает → результат → feedback

Срез, доказывающий продукт = ОДИН инсайт → ОДИН вектор → ОДНО простое действие → «оно реально сделало». БЕЗ мультиагентной команды, скиллбокса, манифеста и 3 параметров на старте — это всё Фазы 2-4.

4. Откуда стартуем (не с нуля)

  • Зеркало: механизм рождения вектора (named insight) задеплоен в PROVODNIK_PROMPT, проверен вживую — сработало. Блок 1 (имя / reset / share) и Блок 2 (гейт сцены) в проде.
  • OpenClaw: установлен на VPS (Амстердам), мозг (DeepSeek) отвечает, gateway поднят на loopback. Фаза A шаги 1-3 ✅. Остались шаги 4-8 (мост).
  • Методология Блока 3 (валидатор / линзы / инсайт / вектор) спроектирована.
  • Хартия агента — этический корень валидатора, черновик.
  • Data model среза — таблицы insight / vector / agent_job созданы и проверены (health 200).

Что уже внутри промпта проводника (bin/yadro-bot/api/main.py), чтобы не дублировать: - порог опор = 3 (на ранних ходах человек тыкает интерфейс — шум среды); - критерий объединяющей силы (ставка связывает ≥2 разрозненных наблюдения, не повтор одного); - градиент уверенности вместо «не уверен — молчи»; - тон ставки «я заметил», не «я понял»; - слой Путь: после подтверждённого вектора — 3-4 живых шага; - образ понижен до опции (кнопка только из явного маркера); - вход переписан (ценность через делегирование, без отрицаний «не анкета/не тест»); - один вопрос за ход, запрет книжных конструкций.

5. ФАЗА 0 — Зеркало выдаёт единицу ценности (без реализатора)

Цель: доказать половину «это про меня». Чисто промт + валидатор, OpenClaw не нужен.

  1. Валидатор как один движок с линзами (инсайт / вектор / петли / запрещённые паттерны), 3 слоя: фильтры (провенанс / новизна / анти-Барнум) → петля подтверждения → дисциплина.
  2. Named insight: провизорный → подтверждённый реакцией человека; не каждый ход; подаётся гипотезой, не вердиктом.
  3. Вектор: конвейер присвоение + энергия + движение → статус «подтверждён».
  4. Делегируемые задачи помечаются типом петли: живое / присвоенное / чужое-надо.
  5. Хартия — в первые токены промта (корень).

Выход: подтверждённый инсайт + подтверждённый вектор + список делегируемых задач. Метрики: time-to-first-insight ≤ 8 ходов; на 30 сообщений — сколько ставок сделано / подтверждено (иначе порог 3 не откалибровать).

6. ФАЗА 1 — Минимальный хэндофф + простейший реализатор ⟵ СРЕЗ

Цель: доказать вторую половину — «оно сделало». Гейт: завершить мост OpenClaw (шаги 4-8).

6.1. Data model (3 таблицы — потолок, не полная схема v4)

insight(id, user_id, run_id, text, motive, anchors_json, created_at)
  -- пишем ТОЛЬКО подтверждённое человеком
vector(id, user_id, insight_id, name, sphere, journey_json, created_at)
  -- journey пока JSON внутри vector, не отдельная таблица
agent_job(id, user_id, vector_id, action_text, status, result, feedback, created_at)
  status:   предложена → подтверждена → выполняется → готово
  feedback: null | да | нет | частично

Ключевое правило — persist только подтверждённого. Named insight → человек сказал «да, про меня» → ТОЛЬКО ТОГДА пишем. «Нет» → не пишем. Иначе база засорится мусором.

6.2. Стык Elyne ↔ Реализатор (грубо, без инфраструктуры)

Elyne (стенд) → SSH-туннель → один endpoint → OpenClaw (VPS, реализатор)

SSH-туннель — выбор на 100%: понятный, обратимый, не меняет OpenClaw, не открывает gateway наружу. Gateway / auth / monitoring строим только после подтверждения KPI.

6.3. Первое действие (главный продуктовый риск)

Риск не в туннеле и не в БД, а в выборе первого действия. - ❌ Плохо: создать задачу/заметку/план («ИИ сделал текст»). - ❌ Опасно: отправить письмо/пост наружу. - ✅ Класс «решающие неопределённость / подготовительные».

Выбрано: «Собрать первый реальный шаг» с элементом внешнего ресёрча. Пример «хочу начать свой проект» → - краткое описание проекта; - находит ~10 похожих решений → обзор рынка → свободная ниша (хотя бы один элемент реального внешнего исследования); - 3 гипотезы аудитории; - первый пост (черновик); - следующий шаг.

Выглядит как настоящая работа, но безопасно — наружу ничего не уходит.

6.4. Шаги реализации (с оценкой)

# Шаг Оценка Статус
1 Data model (3 таблицы, миграции по паттерну _add_col) ~1ч ✅ сделано и проверено
2 Persist подтверждённого: маркеры [INSIGHT]/[VECTOR] → парсер пишет только после подтверждения ~2-3ч ⏳ следующий
3 Карточка одного действия в мини-аппе: «Сделать это? [подтвердить]» (фронт + endpoint) ~3-4ч ⏳
4 SSH-стык → реализатор: при подтверждении ставим agent_job, передаём в OpenClaw ~3-4ч ⏳
5 Исполнение + результат: реализатор делает «первый шаг», результат в agent_job.result, мини-апп показывает ~2-3ч ⏳
6 Feedback: «это приблизило тебя к тому, что важно? да/нет/частично» → agent_job.feedback ~1ч ⏳

Итого ядро среза: ~12-16 часов (≈ 2 дня).

6.5. Тройная проверка KPI среза

  1. Тестер непрошено говорит «это про меня».
  2. Тестер говорит «оно реально что-то сделало».
  3. Объективизация: «Ты бы сделал это сам без меня?» Ответ «нет» = реализатор создал настоящую ценность.

Выход Фазы 1 = точка выхода в ранний доступ.

7. Фазы 2-4 (после того как срез доказан)

ФАЗА 2 — Команда из скиллбокса + «Под капотом». Из вектора собирается мультиагентная команда. SOFT skills = роли (маркетолог/дизайнер/диетолог), HARD skills = инструменты/спец-LLM (текст/картинка/видео/финансы…, часть через OpenRouter). Скиллбокс-матчинг: вектор → нужные роли → предложение на согласование. Раздел «Под капотом»: «исходя из диалога тебе нужно X; вижу, ты избегаешь Y — можем снять». Манифест направления и параметры взаимодействия (творчество / самостоятельность / push-vs-guide) — входные настройки команды из контракта портрета. Этика делегирования (Хартия, Закон 5): что оставить себе (творческое ядро), что делегировать; не забирать живые связи (жена/родители).

ФАЗА 3 — Обратная связь → самообучение вкусу. Реализатор произвёл (напр. презентацию) → собираем ОС «как тебе?» → доработки (человек ОБЯЗАН участвовать) → фиксируются как ВКУС/СТИЛЬ → авто-воспроизводятся в следующих итерациях.

ФАЗА 4 — Виток спирали + мега-инсайты между сферами. Следующий круг: «а что в других направлениях?». Два захода: (а) где внимание сфокусировано; (б) где давно не было, но требуется забота. Многовекторный портрет-граф (обсидиан-совместимый): вектор на сферу, сквозные нити = связи. Мега-инсайт — инсайт МЕЖДУ сферами (ребро графа высокой центральности) → входит в ЯДРО человека.

8. Что НЕ делаем сейчас (дисциплина минимализма)

  • Не заводим полную схему v4 (journey/project/tasks отдельными таблицами) — 3 таблицы потолок.
  • Не строим постоянную сеть (gateway/auth/webhooks) до проверки KPI.
  • Не пишем неподтверждённые инсайты.
  • Не делаем обратный цикл спирали в Фазе A — пока feedback = да/нет/частично, и всё. Спираль — важнейшая идея (возможно главный ров), но если параллельно проверять result → new insight → new vector, потеряем понимание, что именно сработало. Следующий этап.
  • Не смешиваем проверку Пути и проверку Named Insight — это разные гипотезы.
  • Отложить конфиг-UI (манифест / 3 параметра / экраны «Под капотом») — первый реализатор берёт дефолты из контракта портрета, не из экрана настроек.
  • Первое действие — только безопасный класс (наружу ничего).

9. Что начинаем прямо сейчас

Гейт перед реализатором — мост OpenClaw. Параллельно идёт Зеркало (не блокируется мостом). Порядок ближайших шагов:

  1. Шаг 2 среза — persist подтверждённого ([INSIGHT]/[VECTOR] → парсер). Зеркало, мост не нужен.
  2. Шаг 3 — карточка одного действия в мини-аппе. Фронт, мост не нужен.
  3. Мост OpenClaw (шаги 4-8 Фазы A: SSH-туннель стенд → loopback-gateway VPS). Гейт реализатора.
  4. Шаги 4-6 среза — стык → исполнение → feedback. После моста.
  5. Прогон на живом тестере (Максим) → замер тройного KPI.

10. Открытые вопросы (на сверку перед/по ходу)

  1. «Собрать первый реальный шаг» — достаточно ли для KPI «оно реально сделало», или нужно ощутимее?
  2. Порог опор = 3 (+ объединяющая сила + живая энергия) — не слишком ли строго, не замолчит ли агент всю сессию? (Отсюда метрика ставок на 30 сообщений.)
  3. Минимальный набор инструментов реализатору на первое действие (автономный агент с широкими правами — безопасность).
  4. Notion: два режима Зеркало/Воплощение — согласовать (это и есть ось Фаз 0→1).
