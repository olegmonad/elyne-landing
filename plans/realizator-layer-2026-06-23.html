Elyne: Зеркало → Путь → Реализатор

Подробный план реализации

Стержень (сформулировал Олег): ров Elyne не в агенте, а в том, что он знает твою карту пути. Агентов будет миллион — агент, который знает карту твоей жизни, один. Всё ниже служит этому.

0. Решения, принятые как база (на подтверждение)

# Развилка Решение Почему
Р1 Проводник vs Реализатор Один агент, три режима (зеркалит → ведёт по Пути → воплощает) Принцип №1: один агент под капотом, одно лицо. Две сущности = юзер видит «двоих», лишняя сложность.
Р2 Имя «Монад» в продукте «Монад/Моня» = имя личного агента Олега (частный случай). В продукте юзер сам именует своего агента + задаёт пол. «Elyne» = пространство/продукт, не агент. Убирает путаницу, которую отметил Олег.
Р3 Где живёт «Путь» Центральная карта-связка между Зеркалом и Воплощением (схема «Я / Зеркало—Воплощение / Путь снизу») Путь — сердце продукта, не вкладка в ряду.
Р4 Переход между слоями Slide + scale + затемнение (не 3D-куб). Главный переход — смысловой: агент замечает вектор → предлагает перейти к воплощению Плавность > эффект; WebView рвёт 3D.
Р5 Объём первой итерации Сначала мост (Фаза A) на Олеге, потом Путь и рост агента Фазовость: не расширяемся, пока не закрыт чекпоинт «это работает на одном человеке».

1. Смысловая модель (три слоя)

        Я
       /  \
  ЗЕРКАЛО — ВОПЛОЩЕНИЕ
       \  /
       ПУТЬ
  • Зеркало — «кто я». Диалог-проводник, сцены, портрет. (Уже есть.)
  • Путь — «куда я иду». Карта движения: векторы → этапы → проекты → шаги. Центр, связка. (Новое, ядро рва.)
  • Воплощение / Реализатор — «как я создаю». Агент берёт следующий участок пути и делает. (Новое.)

Не намерение → задача → агент выполнил, а: намерение → агент замечает вектор → рождается маршрут → следующий шаг → агент помогает воплотить.

2. Data model (новые сущности)

Поверх текущих users / messages / scenes / taste:

2.1 agent_profile (рост агента — «он знает меня на N%»)

agent_id, user_id, name (юзер задаёт), gender (юзер задаёт),
knows: {ценности, цели, стиль_мышления, проекты, окружение, процессы, инструменты, бизнес} → each 0..1,
can:   [структурировать, планы, тексты_в_тоне, ...] (активные навыки),
opens: [документы, сайты, автоматизации, продажи, ...] (доступные к подключению),
knows_pct (вычисляемый)

2.2 journey (Путь) — главная новая сущность

journey_id, user_id, name ("Выход в проявленность"),
current_stage, vector (главный),
stages: [
  { stage, name, purpose, why_important, related_spheres[], progress, tasks[] }
]

2.3 project (между вектором и задачами)

project_id, user_id, journey_id, name,
vector, status, tasks[]   // задачи живут ВНУТРИ проекта/этапа, не плоским списком

2.4 agent_job / agent_run (исполнение — из правок GPT)

agent_job:  job_id, user_id, project_id, title, sphere, status
            (предложена|подтверждена|выполняется|готово), result
agent_run:  run_id, job_id, step, model_used, log, output, ts

Источник правды — БД. USER.md / портрет агента = кэш + снапшоты (как договорились по OpenClaw).

3. UX по слоям

3.1 Зеркало (есть) + триггер перехода

В диалоге агент ловит намерение-вектор и предлагает карточку:

«Похоже, здесь появился важный вектор. Хочешь, я разложу это в маршрут?»

Тап → плавный переход на Путь (не сразу в задачи).

3.2 Путь (новое, центр)

  • Карта: текущий вектор + этапы с прогрессом (●●●○○ 60%).
  • Каждый этап раскрывается: смысл / почему важно / связанные сферы / шаги / прогресс.
  • Внизу этапа — кнопка Реализатора: «Хочешь, помогу пройти этот этап?»
  • Сферы — карта, не список: видно где движение, где застой, что сейчас главное.

3.3 Реализатор / Воплощение (новое)

  • Шапка: имя агента + статус («2 действия · 1 проект · агент учится»).
  • Предлагает (янтарный борт): что сделает пошагово + «Да, делай / Уточнить». Строка: «Я предлагаю — ты решаешь».
  • В работе: карточки со статусом (предложена/подтверждена/выполняется ◌/готово ✓). Метка сферы на каждой — чтобы не Todoist.
  • Готово: результат разворачивается в карточке + «что дальше».
  • Задачи сгруппированы по проектам, не плоско. Три уровня: простые действия / проектные / системные.

3.4 «Чему меня научить» (рост агента)

Не «магазин плагинов», а развитие: - «Я уже умею для тебя»: ✓ структурировать, ✓ планы, ✓ тексты в тоне; ○ календарь, ○ сайты, ○ продажи… - Карта меня: ✓ ценности, ✓ стиль; ○ окружение, ○ финансы… - «Чем лучше я знаю твои цели и проекты — тем точнее воплощаю».

4. Движки (LLM) — «новичку машина, продвинутому капот»

  • Простой слой (по умолчанию): ⚡ Быстро / 🧠 Глубоко / 🚀 Максимальная мощность. Без имён моделей.
  • «Подробнее о движке» (для продвинутых): какие модели, назначение, возможности, ограничения.
  • Будущее — оркестратор: на задачу «создать проект» Elyne сама берёт модель под стратегию / код / анализ / визуал. Юзер видит результат, при желании — какой двигатель работал.
  • Технически: OpenRouter = выбор «мозга»; FAL и пр. = навыки (opens). Оба уже в движке (OpenClaw + OpenRouter).

5. Фазовость (как строим)

Фаза A — МОСТ (сейчас, только на Олеге) — доказать сквозняк

  1. /api/handoff Зеркало→агент (на мне, через ClaudeClaw; для юзеров — OpenClaw).
  2. Портрет elyne.db → контекст агента (+ origin_vector / intent_reason / desired_outcome).
  3. agent_job/agent_run — минимальное состояние.
  4. Карточка подтверждения (Модель 2): намерение → предложение → confirm → execute.
  5. Кнопка «в работу» + один сквозной сценарий e2e. KPI: агент делает то, что обычный backend+очередь не может (автономный шаг, не только «мозг думает»).

Фаза B — ПУТЬ

  1. journey + project data model.
  2. Экран Пути (карта этапов), триггер «разложу в маршрут» из диалога.
  3. Задачи переезжают внутрь проектов/этапов.

Фаза C — РОСТ АГЕНТА + ДВИЖКИ

  1. agent_profile (knows %, can, opens), экран «Чему меня научить».
  2. Именование агента + пол при онбординге.
  3. Слой движков (простой + капот), затем оркестратор.

Фаза D — ПЕРЕПИСЫВАНИЕ ФРОНТА

Текущий React-миниапп → серьёзный движок (отдельная оценка), когда модель устаканится.

6. Риски (держим в уме)

  1. Todoist-in-disguise — задачи без Пути/сфер убивают идентификацию. Фикс: задача всегда внутри проекта + метка сферы.
  2. Агент решает без спроса — любое внешнее действие только через карточку подтверждения. Это продуктовое обещание, не UX-деталь.
  3. Техно-пульт — слова «модель/провайдер/API» в основном интерфейсе запрещены; только язык результата.
  4. Строим всё сразу (главный) — Phase 0 ещё не закрыт (Аня: «похоже на обычный чат»). Не идём в Путь/рост, пока мост не доказан на одном человеке.

7. Нейминг (итог)

  • Elyne — пространство/продукт.
  • Личный агент юзера — имя и пол задаёт юзер при онбординге.
  • Монад/Моня — имя личного агента Олега (частный случай).
  • Слои: Зеркало (кто я) · Путь (куда иду) · Воплощение/Реализатор (как создаю). Нейминг последнего слоя — «Воплощение» теплее «Делает».
