Elyne — операционная система развития человека

Итоговая архитектура (v2) · на согласование

Что это теперь. Было: AI-проводник + генератор сцен. Стало: AI + агент действий. Теперь: операционная система развития человека.

Где ров. LLM будут у всех. Агенты будут у всех. Автоматизации будут у всех. А накопленная карта человека + история его пути + агент, который развивается вместе с ним — это долгосрочная ценность, которую нельзя догнать.

0. Граница (читать первым)

Это последняя итерация концепции. Документ заморожен на v2. После согласования с Сергеем — не расширяем идею, а идём проверять на Олеге (Фаза A). Риск «бесконечно проектировать идеальную систему» — реальный и назван; защита от него встроена в раздел 7 (фазовость).

1. Философия: как рождается путь

Ядро — причинная цепь. Не «сообщение → задача», а:

диалог
  ↓
insight        ← момент осознания («я понял, что хочу создавать, а не консультировать»)
  ↓
вектор         ← направление, родившееся из инсайта
  ↓
путь (journey) ← живая карта движения
  ↓
проект
  ↓
задача
  ↓
действие → результат

Из инсайтов рождается путь. Это и есть «карта человека» — то, что Сергей в методологии портрета называл способом-быть. insight — мостик между разговором и путём; он делает портрет причинным, а не описательным.

2. Один спутник — три способности (НЕ три режима)

Агент НЕ «переключает режимы» (зеркалит → ведёт → выполняет). Это снова ощущалось бы как программа.

Это один спутник с тремя способностями: - видеть меня (Зеркало), - помнить мой путь (Путь), - помогать воплощать (Реализатор).

Юзер не должен чувствовать переключение. Он должен чувствовать: «он со мной развивается». Это требование к тону и к промпту агента, не только к UI.

3. Смысловая модель (три слоя, Путь — центр)

        Я
       /  \
  ЗЕРКАЛО — ВОПЛОЩЕНИЕ
       \  /
       ПУТЬ
  • Зеркало — «кто я». Диалог, сцены, портрет. (Есть.)
  • Путь — «куда я иду». Центр и связка. Живая карта: векторы → этапы → проекты → шаги. (Ядро рва.)
  • Воплощение / Реализатор — «как я создаю». Спутник берёт следующий участок пути и делает. (Новое.)

4. Путь — живой, не сгенерированный навсегда

Главный риск: ИИ выдал «твой путь: 1. Проявленность 2. Бизнес 3. Публичность» → человек: «почему ИИ решил мой путь?».

Принцип: Путь — это компас + текущая карта, а не маршрут навигатора.

Формулировка в интерфейсе:

«Это не план, которому нужно следовать. Это текущая карта, которую мы видим из твоего состояния сейчас.»

Технически — версионирование: journey_versions (Путь v1 — 15 июня, v2 — 1 августа). Появляется эффект: «посмотри, как изменился твой путь за 3 месяца». Траектория во времени = накопленная ценность.

5. Слой «сейчас» — текущий фокус

Жизнь огромная: путь может содержать «создать проект / стать публичным / улучшить здоровье». Но агент работает не со всем сразу, а с текущим фокусом:

Главный фокус недели: собрать первую аудиторию.

current_focus — то, с чем агент работает в первую очередь. Без него Путь — карта без «здесь и сейчас».

6. Data model (полная — реализуется по слоям, см. §7)

Поверх текущих users / messages / scenes / taste:

6.1 insight

insight_id, user_id, source_message_id, text, ts

Момент осознания, извлечённый из диалога. Родитель векторов.

6.2 vector

vector_id, user_id, insight_id, name, sphere

6.3 journey + journey_versions

journey:          journey_id, user_id, name, current_stage, current_focus
journey_versions: version_id, journey_id, version_no, snapshot(JSON), created_at
stage (в snapshot): { stage, name, purpose, why_important, related_spheres[], progress }

6.4 project

project_id, user_id, journey_id, vector_id, name, status, tasks[]

Задачи живут ВНУТРИ проекта/этапа, не плоским списком.

6.5 agent_profile (рост спутника)

agent_id, user_id, name(юзер задаёт ПОЗЖЕ), gender,
knows: {ценности, цели, стиль, проекты, окружение, процессы, инструменты, бизнес}→0..1,
can[], opens[], knows_pct

6.6 agent_job / agent_run (исполнение)

agent_job: job_id, user_id, project_id, title, sphere,
           status(предложена|подтверждена|выполняется|готово), result
agent_run: run_id, job_id, step, model_used, log, output, ts

Источник правды — БД. Кэш агента (USER.md/портрет) = снапшоты.

7. Фазовость — защита от переусложнения

Фаза A — ВЕРТИКАЛЬНЫЙ СРЕЗ (сейчас, только Олег). Не строим модель вширь — берём по одному экземпляру каждой сущности через всю цепь:

Олег говорит с агентом
  ↓ агент замечает ОДИН вектор (через 1 insight)
  ↓ создаётся МАЛЕНЬКИЙ путь (1 этап)
  ↓ предлагает ОДНО действие (карточка подтверждения, Модель 2)
  ↓ делает → показывает результат

Реализуется минимум: insight(1) → vector(1) → journey(1 stage) → agent_job(1) + мост Зеркало→агент (на Олеге через ClaudeClaw; для юзеров — OpenClaw) + портрет elyne.db→контекст агента. KPI: агент делает то, что обычный backend+очередь не может.

Фаза B — ПУТЬ вширь. Полный journey + journey_versions + current_focus, экран карты, триггер «разложу в маршрут».

Фаза C — РОСТ СПУТНИКА + ДВИЖКИ. agent_profile (knows %), экран «разрешить помогать больше», именование агента, слой движков → оркестратор.

Фаза D — ПЕРЕПИСЫВАНИЕ ФРОНТА на серьёзный движок (отдельная оценка), когда модель устаканилась.

Версии пути / фокус / рост агента — в схему закладываем, кодим в B–C, не в A.

8. UX по слоям

8.1 Зеркало → триггер (смысловой переход)

Агент ловит намерение и предлагает:

«Похоже, здесь появился важный вектор. Хочешь, разложу это в маршрут?»

Тап → плавный переход (slide + scale + затемнение, без 3D-куба) на Путь.

8.2 Путь (центр)

Карта вектора + этапы с прогрессом (●●●○○ 60%). Этап раскрывается: смысл / почему важно / связанные сферы / шаги. Сферы — карта, не список (видно где движение, где застой). Внизу этапа: «Помочь пройти этот этап?».

8.3 Воплощение / Реализатор

  • Шапка: имя спутника + «2 действия · 1 проект · учится».
  • Предлагает (янтарный борт): шаги + «Да, делай / Уточнить» + «Я предлагаю — ты решаешь».
  • В работе: статусы (предложена / подтверждена / выполняется ◌ / готово ✓), метка сферы на каждой.
  • Готово: результат в карточке + «что дальше».
  • Группировка по проектам. Три уровня действий: простые / проектные / системные.

8.4 «Разрешить мне помогать больше» (рост, не «магазин плагинов»)

Не функция → польза:

Сейчас я могу: ✓ думать вместе с тобой. Подключишь календарь → ✓ помогу беречь время. Подключишь почту → ✓ помогу вести коммуникации.

Плюс «Карта меня»: ✓ ценности, ✓ стиль; ○ окружение, ○ финансы… — видно развитие.

9. Онбординг — имя рождается после связи

Имя = эмоциональная связь, нельзя просить на холодную.

Elyne
  ↓ спутник начинает узнавать тебя
  ↓ после первой сцены / первого пути:
"Хочешь дать ему имя?" (+ пол)

До этого момента — просто «твой спутник». Ничего не просим до wow.

10. Движки (LLM) — «новичку машина, продвинутому капот»

  • По умолчанию: ⚡ Быстро / 🧠 Глубоко / 🚀 Максимальная мощность (без имён моделей).
  • «Подробнее о движке» — для продвинутых: какие модели, назначение, ограничения.
  • Будущее — оркестратор: на «создать проект» Elyne сама берёт модель под стратегию / код / анализ / визуал.
  • Технически: OpenRouter = выбор «мозга»; FAL и пр. = навыки (opens).

11. Нейминг (итог)

  • Elyne — пространство/продукт.
  • Спутник юзера — имя и пол задаёт юзер, ПОСЛЕ узнавания.
  • Монад/Моня — имя личного спутника Олега (частный случай).
  • Слои: Зеркало (кто я) · Путь (куда иду) · Воплощение (как создаю). «Воплощение» теплее «Делает».

12. Риски

  1. Todoist-in-disguise — задача всегда внутри проекта + метка сферы.
  2. Агент решает без спроса — только через карточку подтверждения (продуктовое обещание).
  3. Техно-пульт — слова «модель/провайдер/API» в основном интерфейсе запрещены.
  4. Путь как приговор — формулировка «текущая карта, не план» + версии.
  5. Переусложнение первой версии (главный) — Фаза A = вертикальный срез; концепция заморожена.

13. Вопросы Сергею (на согласование)

  1. insight как формализация способа-быть из методологии портрета — ложится ли на твою модель L1? Где граница между «инсайтом» и «вектором»?
  2. Путь как «компас + живая карта» (версии во времени) — согласуется ли с тем, как ты видишь развитие человека?
  3. Три способности одного спутника (видеть / помнить / воплощать) — нет ли потери «проводника» в момент, когда он начинает «делать»?
  4. Тон перехода Зеркало→Воплощение — где грань, за которой «воплощение» убивает созерцательность Зеркала?
