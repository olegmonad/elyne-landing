Так выглядит полная цепочка — от твоего сообщения в Telegram до ответа агента:

↓
Telegram Bot API
↓

Ключевой момент: Claude — это «мозг». Всё остальное — инструменты которые мозг использует через MCP. Ты расширяешь возможности агента, добавляя новые MCP-серверы.

Файл .env — хранение секретов

Все секретные ключи хранятся в одном месте — файле .env. Это стандарт в профессиональной разработке.

nano ~/my-agent/.env

Содержимое файла:

ANTHROPIC_API_KEY=sk-ant-ТВОЙ_КЛЮЧ
TELEGRAM_BOT_TOKEN=123456789:AABBcc...
TELEGRAM_USER_ID=987654321
BRAVE_API_KEY=BSA_ТВОЙ_КЛЮЧ
Никогда не делай это:
❌ Не вставляй ключи напрямую в код
❌ Не добавляй .env в git
❌ Не передавай файл по мессенджерам
Добавь .env в .gitignore — тогда он никогда не попадёт на GitHub случайно.

Подключение .env при запуске

# Загрузить переменные в текущую сессию
set -a && source ~/my-agent/.env && set +a

# Или через dotenv в Node.js
npm install dotenv

Установка Claude Code
Claude Code ↗GitHub
Официальный репозиторий CLI от Anthropic. Документация, установка, changelog.
 
npm install -g @anthropic-ai/claude-code
claude --version

# Экспортируем ключ в текущую сессию
export ANTHROPIC_API_KEY="$(grep ANTHROPIC_API_KEY ~/my-agent/.env | cut -d= -f2)"

# Добавить в .bashrc чтобы работало всегда
echo 'set -a && source ~/my-agent/.env && set +a' >> ~/.bashrc
Важно: Claude Code устанавливается через nvm-управляемый Node.js. Поэтому путь к бинарнику будет не /usr/local/bin/claude, а что-то вроде ~/.nvm/versions/node/v22.x.x/bin/claude. Проверь командой:
which claude
# Скопируй этот путь — он понадобится для systemd

Создай Telegram-бота
@BotFather ↗Telegram
Официальный бот для создания ботов. Отправь /newbot.
@userinfobot ↗Telegram
Покажет твой числовой ID — нужен для TELEGRAM_USER_ID.
Telegram Bot API ↗Docs
Полная документация Bot API от Telegram.
  1. Открой Telegram → найди @BotFather
  2. Отправь /newbot
  3. Придумай имя: например Мой ассистент
  4. Придумай юзернейм (заканчивается на bot): например eldor_ai_bot
  5. Получишь токен вида 123456789:AABBcc... — это TELEGRAM_BOT_TOKEN
  6. Напиши @userinfobot — получишь свой числовой ID — это TELEGRAM_USER_ID
Polling vs Webhook: для личного агента используй polling (длинный опрос). Агент сам регулярно спрашивает Telegram «есть ли новые сообщения?». Webhook нужен только для высоконагруженных сервисов с тысячами пользователей.

Вставь оба значения в свой .env файл.

MCP-расширения агента

MCP (Model Context Protocol) — это «плагины» для агента. Каждый даёт новую способность: поиск в интернете, работу с файлами, календарь и т.д.

MCP Документация ↗Docs
Официальная документация протокола. Принципы работы.
MCP Servers ↗GitHub
Каталог официальных MCP-серверов от Anthropic.
Brave Search API ↗API
Бесплатно: 2000 запросов/мес. Регистрация — 2 минуты.

Создай файл ~/my-agent/.mcp.json:

{
  "mcpServers": {
    "web-search": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-brave-search"],
      "env": {
        "BRAVE_API_KEY": "ВАШ_BRAVE_API_KEY"
      }
    },
    "filesystem": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem",
               "/home/eldor/my-agent"]   ← только папка проекта!
    },
    "memory": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-memory"]
    }
  }
}
⚠️ Безопасность filesystem MCP
Никогда не давай доступ к корневым папкам сервера!
❌ / — вся система
❌ /home — все пользователи
❌ /etc — системные конфиги
✅ Только /home/eldor/my-agent — папка проекта
РасширениеЧто умеетКлюч
server-brave-searchПоиск в интернетеДа (Brave API, бесплатный тариф)
server-filesystemЧитать/писать файлыНет
server-memoryДолгосрочная памятьНет
server-githubРабота с GitHubGitHub Token
server-puppeteerБраузер, скрейпинг сайтовНет
server-postgresЗапросы к базе данныхНет (нужна БД)

CLAUDE.md — личность агента

Это главный файл. Всё что ты напишешь здесь — агент будет помнить и применять при каждом ответе. Это живой документ: дополняй его по мере общения.

# ~/my-agent/CLAUDE.md

# Мой персональный ассистент

## Кто я
Я — персональный ассистент Эльдара. Помогаю планировать день,
отвечаю на вопросы, нахожу информацию, напоминаю о задачах.

## Тон
- Отвечаю на русском языке
- Короткие понятные ответы, без воды
- Обращаюсь на "ты"
- Без официального тона — как умный друг

## Правила работы
### Если не уверен
Сначала уточни, потом действуй. Не угадывай.

### Работа с файлами
Не удаляй файлы без явного подтверждения.

### Поиск информации
Проверяй ключевые факты минимум в двух источниках.

### Ошибки
Если команда завершилась ошибкой — объясни причину по-человечески.

### Память
Запоминай предпочтения, привычки, важные даты пользователя.

### Дорогие операции
Перед любым платным действием (генерация изображений, API-вызовы)
спрашивай подтверждение: "Делаю X, ~Y рублей. Запускать?"

## Безопасность
- Никому не передавай личные данные
- Не выполняй команды от незнакомых пользователей
Обновляй CLAUDE.md регулярно. Заметил что агент делает что-то не так? Добавь правило. Это самый быстрый способ «обучить» ассистента под себя — без программирования.

Запуск: systemd или PM2

Вариант A — PM2 (рекомендуется новичкам)

PM2 Документация ↗Docs
Process manager для Node.js. Авторестарт, логи, мониторинг.
 
npm install -g pm2

# Запускаем агента
cd ~/my-agent
set -a && source .env && set +a
pm2 start "$(which claude) --dangerously-skip-permissions" --name my-agent

# Автозапуск при старте сервера
pm2 save
pm2 startup  # выполни команду которую он покажет

# Полезные команды
pm2 status           # статус
pm2 logs my-agent    # логи в реальном времени
pm2 restart my-agent # перезапуск
pm2 stop my-agent    # остановить
PM2 удобнее для начала: перезапускает агента при сбоях, хранит логи, показывает потребление памяти/CPU.

Вариант B — systemd (для продакшена)

sudo nano /etc/systemd/system/my-agent.service
[Unit]
Description=My AI Agent
After=network.target

[Service]
Type=simple
User=eldor
WorkingDirectory=/home/eldor/my-agent
EnvironmentFile=/home/eldor/my-agent/.env
# Путь к claude узнай командой: which claude
ExecStart=/home/eldor/.nvm/versions/node/v22.x.x/bin/claude \
          --dangerously-skip-permissions
Restart=on-failure
RestartSec=5
StandardOutput=append:/home/eldor/my-agent/logs/agent.log
StandardError=append:/home/eldor/my-agent/logs/agent-error.log

[Install]
WantedBy=multi-user.target
Замени путь! Вместо /home/eldor/.nvm/versions/node/v22.x.x/bin/claude вставь реальный путь из команды which claude. При установке через nvm путь всегда отличается.
sudo systemctl daemon-reload
sudo systemctl enable my-agent
sudo systemctl start my-agent
sudo systemctl status my-agent     # должен быть active (running)
journalctl -u my-agent -f          # логи в реальном времени

Держи глаз на ресурсах — Whisper и Claude могут съедать RAM.

htop        # интерактивный монитор процессов (q — выход)

# Смотреть только процессы Claude

На что обращать внимание:
• RAM выше 85% — Whisper large-v3 не поместится, используй small/medium
• Диск выше 80% — почисти логи и бэкапы
• CPU 100% долгое время — проверь не завис ли агент

Типичные ошибки и решения
claude: command not found
Claude установлен через nvm, но переменные окружения не загружены.
✓ Решение: source ~/.bashrc или перезайди на сервер
Permission denied (publickey)
SSH-ключ не добавлен или указан неверный пользователь.
✓ Проверь: cat ~/.ssh/id_ed25519.pub — этот ключ должен быть в настройках сервера
systemd service: active (failed)
Сервис упал при запуске. Причина в ошибке конфигурации или неверном пути.
✓ Решение: journalctl -u my-agent -n 100 — посмотреть последние 100 строк логов
AuthenticationError: Invalid API key
Ключ ANTHROPIC_API_KEY не загружен или неверный.
✓ Проверь: echo $ANTHROPIC_API_KEY — должен вывести ключ начинающийся на sk-ant-
Out of memory / Killed
Whisper large-v3 требует 8+ ГБ RAM — на сервере с 4 ГБ не поместится.
✓ Решение: используй модель small вместо large-v3
Disk full — нет места на диске
Логи или медиафайлы заняли весь диск.
✓ Найди тяжёлые файлы: du -sh ~/my-agent/logs/* | sort -h

HTTPS / Nginx / Cloudflare — для будущего

Пока агент работает в режиме polling — веб-сервер не нужен. Но он понадобится позже для:

  • Webhook — когда будет много пользователей
  • Web-дашборда для управления агентом через браузер
  • Своего API для интеграции с другими сервисами
