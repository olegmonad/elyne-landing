Цель: свести разрозненную «модель личности» (сейчас размазана по insight/vector/sphere_profiles) в единое ядро наблюдений с уверенностью, статусом и дисциплиной обновления — и подключить к нему запись проводника. Без экрана (это ТЗ-2) и без ночного консолидатора (ТЗ-3).

Ключевое правило (из архитектуры, соблюсти): проводник НИКОГДА не пишет факт — только proposed. Повышение — через юзера или консолидатор.

Задача 1 · Таблица self_model

Новая таблица — единый слой наблюдений поверх существующих (не ломаем insight/vector; они остаются, приложение на них завязано). self_model = источник правды для будущего экрана «Моя модель».

CREATE TABLE self_model (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  tg_user_id    INTEGER NOT NULL,
  run_id        INTEGER NOT NULL DEFAULT 1,
  kind          TEXT NOT NULL,                       -- identity|insight|vector|sphere|motif|taste|value|preference
  key           TEXT,                                -- краткий ярлык наблюдения (для дедупа/группировки)
  value         TEXT NOT NULL,                       -- формулировка «как я его понял»
  confidence    REAL NOT NULL DEFAULT 0.3,           -- 0.0–1.0
  status        TEXT NOT NULL DEFAULT 'proposed',    -- proposed|confirmed|integrated|superseded
  source        TEXT NOT NULL DEFAULT 'provodnik',   -- provodnik|validator|user|consolidator
  anchors       TEXT,                                -- JSON-массив цитат-доказательств из реплик
  motive        TEXT,                                -- для kind=insight/vector
  sphere        TEXT,                                -- для kind=vector/sphere
  origin_insight_id INTEGER,                         -- мост со старой таблицей insight.id
  origin_vector_id  INTEGER,                         -- мост со старой vector.id
  supersedes    INTEGER,                             -- id наблюдения, которое это уточняет/заменяет
  locked        INTEGER NOT NULL DEFAULT 0,          -- 1 = ядро, что юзер закрепил (не менять авто)
  created_at    TEXT NOT NULL,
  updated_at    TEXT NOT NULL
);
CREATE INDEX idx_self_model_user ON self_model(tg_user_id, run_id, status);
CREATE INDEX idx_self_model_kind ON self_model(tg_user_id, kind);

Создавать идемпотентно при старте (рядом с прочими _add_col/CREATE TABLE IF NOT EXISTS в инициализации схемы).

Задача 2 · Проводник пишет proposed-наблюдения

Точка встройки: тот же блок /api/chat, main.py:2522–2570, СРАЗУ после существующих INSERT в insight/vector (оставляем их — двойная запись на переходный период).

Добавить хелпер и вызвать его:

def _sm_observe(db, uid, run, kind, value, *, key=None, anchors=None,
                motive=None, sphere=None, source="provodnik",
                seed_conf=0.30, origin_insight_id=None, origin_vector_id=None, now=None):
    """Кладёт наблюдение в self_model. Если такое уже есть (тот же kind + похожий key/value
    в этом прогоне) — не плодит дубль, а ПОВЫШАЕТ уверенность (независимый сигнал) и
    доклеивает опоры. Проводник пишет только proposed."""
    dedup_key = (key or value).strip().lower()[:120]

Проводник только создаёт proposed и повышает при повторе. Подтверждение юзером (confirmed/locked) и integrated — в ТЗ-2/ТЗ-3.

Расчёт confidence (точные правила)

Посев (seed) при первом наблюдении — по источнику/качеству:

Ситуация seed
Проводник, обычное наблюдение 0.30
Прошло гейт Валидатора (insight provisional: 4 фильтра + ≥2 опоры) 0.45
Прямой маркер модели confirmed (после подтверждения в диалоге, логика 2526) 0.70
Явное подтверждение юзером (ТЗ-2) 0.90 + locked=1

Корроборация: повторное независимое наблюдение того же (kind+key) → confidence += 0.15, потолок 0.95, опоры сливаются. Дубли не плодим.

Переходы статуса (машина состояний): - proposed — confidence < 0.7 и не подтверждён юзером. - confirmed — confidence ≥ 0.7 и юзер не возразил, или явное подтверждение юзером. - integrated — выставляет ночной консолидатор (ТЗ-3), колонка уже есть. - superseded — при уточнении: у нового supersedes=<old_id>, у старого status='superseded'.

В этом ТЗ проводник доводит только до proposed→(рост conf). Автоперевод в confirmed по порогу — оставить хук, но включить в ТЗ-2 вместе с экраном (иначе подтверждать нечем).

Критерии приёмки

  1. После хода диалога с [INSIGHT]/[VECTOR] в self_model появляется строка: source=provodnik|validator, status=proposed, confidence 0.30–0.70, anchors заполнены, origin_insight_id/origin_vector_id проставлены.
  2. Повтор того же инсайта следующим ходом не создаёт дубль — повышает confidence существующей строки и доклеивает опоры (проверяется в логе/БД).
  3. Бэкфилл дал число строк, соответствующее текущим insight+vector+sphere+identity+taste.
  4. Регрессии нет: insight/vector пишутся как раньше; Путь/сцены/дашборд не сломаны.
