2. Статус багов из v1

BUG-01 (HIGH) — CreateScenePhotoAction пропускает face guard

Статус: подтверждён, дамп не опровергает.

В БД промт image_instructions (id=12, 5.4 KB) — существует. Это и есть face guard, который должен вызываться из getImageInstructions(). Аудит кода 26.05 показал, что CreateScenePhotoAction его не вызывает. Дамп подтверждает: промт лежит, но в pipeline three_angles_scene не подключается → лица могут плыть на trios.

Что чинить: Денису — добавить getImageInstructions() в CreateScenePhotoAction (как в обычной single-scene action).

BUG-02 (MEDIUM → HIGH после расширения) — опечатки в мета-промте AI-вопросов

В прошлом аудите я назвал это «опечатка изместно в ID=21». Точный адрес — generation_prompts id=21 (тип ai_questionnaire_question), не questionnaire_questions. Промт длиной 356 байт. В нём три опечатки, не одна.

Полный текст:

Cформулируй ОДИН уточняющий вопрос пользователю для сферы {sphere_title}
вот что изместно о пользователе: {gender} {profile_summary}
Вот ответы которые он дал ужн для этой сферы {micro_adjustment_answers}
Задай один важный уточняющий вопрос чтобы у нас была более персонализированная и детализированная под пользователя сцена его жизни для этой сферы
# Опечатка Должно быть Где
1 Cформулируй Сформулируй 1-й символ. Латинская C (U+0043) вместо кириллической С (U+0421)
2 изместно известно строка 2
3 ужн уже строка 3

Этот промт уходит в LLM каждый раз при генерации Q3-вопроса (повторяющийся вопрос перед каждой сценой). Псевдо-слова «изместно» и «ужн» могут сбивать LLM: модель пытается интерпретировать как термин и теряет инструкцию.

Что чинить: через админку elyne.online/admin перезаписать meta_prompt id=21. Готовый правильный текст:

Сформулируй ОДИН уточняющий вопрос пользователю для сферы {sphere_title}
Вот что известно о пользователе: {gender} {profile_summary}
Вот ответы которые он уже дал для этой сферы {micro_adjustment_answers}
Задай один важный уточняющий вопрос — чтобы получилась более персонализированная и детализированная сцена его жизни для этой сферы.

NOTE-03 (закрыто) — three_angles_scene не найден в БД

Снято. В v1 я не нашёл этот тип, потому что сервер таймаутил на странице. По дампу: - В ENUM generation_prompt_type строка 10 — three_angles_scene есть - В таблице — запись id=18, field_name «Три угла», meta_prompt 7.7 KB - Промт активен. Но в sphere_selector_configs.three_angles_enabled = false → на проде выключен. Промт реализован, но в конфиге не включён. Это не runtime error, это product-decision Дениса/Олега.

NEW-02 (MEDIUM) — Сфера «Тренды» (id=11) добавлена 17.05

В БД 11 сфер, а ты фиксировал ровно 10 (msg_2002, 29.04).

11-я сфера: - id=11, slug=trends, name=Тренды - Создана 2026-05-17 13:05, последнее обновление 25.05 - excluded_from_selector: false → юзер её видит в селекторе - is_clone_source: true → используется как шаблон-источник для клонирования - sort_order: 11 - Описание: «Сфера актуального — то, что формирует дух времени: технологии, медиа, культура, стиль жизни, бизнес-паттерны и социальные сдвиги»

Денис либо ты сам решил добавить — я в логе TG не нашёл явного согласования. Может быть, это служебная для тестов кросс-клонирования (is_clone_source=true намекает), но excluded_from_selector=false делает её видимой на проде.

Что решить: оставляем 11-ю сферу как продакшн? Если нет — excluded_from_selector=true. Если служебная — выключить из селектора и переименовать (например, slug _template).

NEW-03 (MEDIUM) — slug онбординга с пробелами и опечаткой ломает URL

Та самая «How%20it%20worrks» из QA 26.05.

onboarding_pages id=41: - slug: "How it worrks" ← пробелы + заглавная + опечатка - type: editorial_presentation - sort_order: 5 — пятый экран онбординга

Три проблемы в одном поле: 1. Опечатка worrks → works 2. Пробелы в slug → URL получает %20 → роутер ломается с ERR_ABORTED 3. Заглавная буква — конвенция slug = lowercase kebab-case

Что чинить: в админке переименовать slug в how-it-works. Проверить, что нигде в коде нет хардкода How%20it%20worrks (вряд ли — это поле берётся из БД).
