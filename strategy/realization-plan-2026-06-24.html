План реализации: Зеркало → Реализатор (по видению Олега 24.06)

Запрос Олега (msg_682): продумать пошаговый план реализации спирали Зеркало→Воплощение + что скорректировать. Олег развернул полную картину: инсайт→вектор→мультиагентная команда из скиллбокса→манифест-параметры→самообучение вкусу→следующий виток спирали→мега-инсайты между сферами→ядро.

ГЛАВНАЯ КОРРЕКЦИЯ (читать первой)

Олег нарисовал ВЕСЬ собор. Если строить его целиком — не выкатим никогда. Правило: строим тонкий вертикальный срез, потом наслаиваем богатство. - Срез, доказывающий продукт = ОДИН инсайт → ОДИН вектор → ОДНО простое действие реализатора → «оно реально сделало». БЕЗ мультиагентной команды, скиллбокса, манифеста, 3-параметров на старте. - Мультиагентная команда / скиллбокс / манифест / самообучение / мега-инсайты — это Фазы 2-4, НЕ MVP. - Реализатор-фазы гейтятся завершением интеграции OpenClaw (мост Elyne↔OpenClaw, шаги 4-8). Сначала мост, потом команда. - Конфиг-UI (манифест, 3 параметра, экран «Под капотом») — отложить; первый реализатор берёт дефолты из контракта портрета, не из экрана настроек.

ТЕКУЩЕЕ СОСТОЯНИЕ (от чего стартуем, не с нуля)

  • Зеркало: vector-birth механизм задеплоен в PROVODNIK_PROMPT; методология Блока 3 (валидатор/линзы/инсайт/вектор) спроектирована (block3-methodology-spec). Блок 1 (имя/reset/share) + Блок 2 (гейт сцены) в проде.
  • OpenClaw: установлен на VPS NL, мозг (DeepSeek) отвечает, gateway поднят (Фаза A шаги 1-3 ✅). Остались шаги 4-8 (мост).
  • Хартия агента: черновик (этический корень валидатора).

ФАЗА 0 — Зеркало выдаёт единицу ценности (БЕЗ реализатора)

Цель: доказать половину «это про меня». Чисто промт+валидатор, OpenClaw не нужен. 1. Валидатор как один движок с линзами (инсайт/вектор/петли/паттерны), 3 слоя (фильтры провенанс/новизна/Барнум → петля подтверждения → дисциплина). 2. Named insight: провизорный→подтверждённый реакцией; не каждый ход; гипотезой не вердиктом. 3. Вектор: конвейер (присвоение+энергия+движение) до статуса «подтверждён». 4. Делегируемые задачи помечаются типом петли (живое/присвоенное/чужое-надо). 5. Хартия в первые токены промта (корень). Выход: подтверждённый инсайт + подтверждённый вектор + список делегируемых задач. Метрика: time-to-first-insight ≤8, плотность, конверсия (см. метрики спеки).

ФАЗА 1 — Минимальный хэндофф + простейший реализатор (ВЕРТИКАЛЬНЫЙ СРЕЗ)

Цель: доказать вторую половину «оно сделало». Гейт: завершить мост OpenClaw. 1. Мост Elyne-HTTP → OpenClaw gateway (SSH-туннель/rebind+auth; Elyne на 38.180.98.36, gateway loopback). 2. Портрет elyne.db → USER.md + origin_vector/intent_reason/desired_outcome. 3. /api/handoff → OpenClaw; кнопка «в работу»; agent_jobs/runs (статусы). 4. Реализатор = ОДИН OpenClaw-агент, ОДНА простая реальная задача из подтверждённого вектора (ресёрч / черновик / 5 контактов). НИКАКОЙ команды пока. 5. Гейт исполнения (Хартия Закон 2,4): только живое/присвоенное надо; необратимое → поштучное подтверждение. Выход = KPI вертикального среза: «это про меня — и оно что-то реально сделало». Это точка выхода в ранний доступ.

ФАЗА 2 — Команда из скиллбокса + «Под капотом»

  1. Из вектора собирается мультиагентная команда. SOFT skills = роли (маркетолог/дизайнер/диетолог). HARD skills = инструменты/спец-LLM (текст/картинка/видео/дизайн/финансы/фитнес…), часть — через OpenRouter.
  2. Скиллбокс-матчинг: вектор → нужные роли → предложение на согласование («можем добавить такие роли»). Раздел «Под капотом»: «исходя из диалога тебе нужно X; вижу, ты избегаешь Y — можем снять».
  3. Манифест направления / параметры взаимодействия (степень творчества / самостоятельности / push-vs-guide) — входные настройки команды, источник = контракт портрета, surface на подтверждение.
  4. Презентация команды + возможностей → приглашение в реализацию.
  5. Этика делегирования (Хартия Закон 5): спросить, что оставить себе (творческое ядро), что делегировать (подавляющее/блокирующее рост); не забирать всё, не делегировать живые связи (жена/родители).

ФАЗА 3 — Обратная связь → самообучение вкусу

  1. Реализатор произвёл (напр. презентацию) → собираем ОС «как тебе?» → доработки (человек ОБЯЗАН участвовать).
  2. Доработки фиксируются как ВКУС/СТИЛЬ пользователя → авто-воспроизводятся в следующих итерациях (петля портрет←результат, уже в спеке).

ФАЗА 4 — Виток спирали + мега-инсайты между сферами

  1. Переход на следующий круг: «а что в других направлениях?». Два захода — (а) где внимание сфокусировано; (б) где давно не было, но требуется забота (подзаваленные сферы, которые агент разгрузит).
  2. Многовекторный портрет-граф (обсидиан-совместимый): вектор на сферу, сквозные нити = связи.
  3. МЕГА-ИНСАЙТ: инсайт внутри сферы = инсайт; инсайт МЕЖДУ сферами = мега-инсайт (ребро графа высокой центральности) → входит в ЯДРО человека (фундаментальные характеристики).

Что скорректировать в видении (сводно)

  1. Стадировать жёстко — вертикальный срез (Фаза 0+1) до всего остального. Не строить собор разом.
  2. Реализатор-фазы гейтятся OpenClaw — мост (шаги 4-8) первым, потом команда.
  3. Отложить конфиг-UI (манифест/3-параметра/«Под капотом» экраны) — дефолты из контракта портрета, пока ядро не работает.
  4. Мега-инсайты/спираль нужны накопленные данные — Фаза 4, не сейчас.
  5. Этика уже покрыта Хартией — делегирование/зависимость = Закон 5; не дублировать, ссылаться.
