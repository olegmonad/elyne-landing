4. СИСТЕМНЫЕ ПРОБЛЕМЫ (для Дениса)

HIGH — нужно решить до имплементации

1. Тип long отсутствует в библиотеке Runtime-логика ждёт type: "long" при 35+ сек. В JSON v3 таких юнитов нет, size L отсутствует. → Либо добавить 5-7 long-фраз, либо убрать long из runtime и использовать M для 35+ сек.

2. Нет механизма финальной фразы перед reveal Алгоритм знает когда показать reveal, но не знает чем закончить текстовую дугу. → Добавить 2-3 юнита с флагом reveal_proximity: true, показываются только в последние 3-5 сек.

MEDIUM

3. Две несовместимые номенклатуры типов loading_v2_system_logic использует contemplative/brand/future_recognition. runtime_logic_v3 использует emotional/consciousness/long/science_magic. JSON v3 уже в правильной номенклатуре — но v2-документы устарели. Денис получит противоречие. → v2 документы = архив, канон = runtime_logic_v3 + JSON v3.

4. violatesSequenceRules — функция-заглушка В pseudocode упомянута, но не реализована. Без неё правило «3 подряд одного типа» нарушается ~17% времени при весах System A. → Нужна явная реализация в спеке.

5. System B не обеспечена полем system в юнитах В JSON v3 уже стоит system: "grounded_cinematic" или "consciousness_inner_reality" — это решено. Но если Денис возьмёт старые v2 файлы — поля нет. Убедиться что передаётся только v3 JSON.

5. ЧЕГО НЕ ХВАТАЕТ

  • Телесный регистр — 2-3 фразы про физическое ощущение узнавания (кроме A_em_8)
  • Sphere-specific micro — 5-7 фраз привязанных к конкретной сфере (ресурсы, партнёрство...)
  • Антиожидание — 1 фраза которая нормализует несовпадение сцены с ожиданием
  • Разнообразие зачинов — «Иногда» = 42% фраз. Нужны «Бывает», «Порой», безличные конструкции
