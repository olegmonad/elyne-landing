0. TL;DR — Главный диагноз

Три причины, почему Sport Casual побеждает и почему wish-перегенерация сламывает сцену:
  1. Data issue: User 7806 выбрала ТОЛЬКО Sport Casual → нет конкурентов → он доминирует по дизайну системы. Не баг.
  2. Prompt issue: Поле Base Wardrobe в определении стиля содержит буквальный список вещей (свитшот, кроссовки, техническая куртка). LLM читает это как инструкцию → материализует буквально. Запрет на буквальную интерпретацию теряется в горе других инструкций.
  3. Code issue (critical): Тип «Уточнение с комментарием» строит FAL-промпт как wish_text + image_suffix — без scene description, без profile_summary, без style_resolution, без KALs. Фактически — новая генерация из воздуха.

4. Style Resolution Layer — проверка

Ответ на вопрос «Существует ли отдельный style_resolution layer?»

style_resolution layer is NOT implemented as a separate technical layer.

Style resolution существует только как текстовые инструкции внутри profile_summary_system prompt. Алгоритмической логики нет. Система работает так:

  1. User выбирает clothing_styles при онбординге
  2. Все выбранные стили → {chosen_clothing_style} placeholder в meta_prompt (full text включая Base Wardrobe)
  3. Инструкции profile_summary_system говорят LLM «интерпретируй как визуальное направление»
  4. LLM возвращает character_profile JSON со строкой Visual Identity
  5. Эта строка инжектируется обратно как {profile_summary} в meta_prompt

Поля style_resolution_text, character_profile в наших debug JSON — это распарсенный вывод из profile_summary, не отдельный слой.

7. Проверка image_instructions

В admin есть только 2 поля на generation_prompt: meta_prompt и image_suffix. Поля image_instructions, title_meta_prompt, variation_instructions — в коде, не в БД.

Фактическая структура FAL prompt (из дампа):

// Для первой генерации / Перегенерации:
detailed_description (= OpenRouter scene output)
+ image_suffix (= FIRST SCENE VISUAL REALISM ADDITIONS + all cinematic rules + F4+F5)

// Для Уточнения с комментарием (BUG):
wish_text
+ image_suffix

Поля image_suffix содержат (current, GP2):

  • ЕСТЕСТВЕННАЯ СВЕЖЕСТЬ И ЖИВОСТЬ
  • FIRST SCENE VISUAL REALISM ADDITIONS (после F2-F7 апгрейда 18.05)
  • Visual Realism Rules
  • Human Presence Rules
  • Cinematic Atmosphere Rules
  • Modern Clothing Rendering
  • Emotional Visual Amplification
  • Identity Refinement Layer
  • F4+F5 CINEMATIC UPGRADE (Cultural Assumption Filter + Camera Grammar)

НЕТ прямых инструкций усиливающих sneakers/cargo/technical jacket/sport chic/urban mobility в image_suffix.

Буквализация Sport Casual wardrobe происходит на уровне OpenRouter scene generation, не FAL suffix.

8. Структура первой сцены

Отдельных правил «first scene is more aspirational» в коде нет. First scene логика встроена в:

  • meta_prompt: секция «## FIRST SCENE PRODUCTION LAYERS» (6 слоёв)
  • meta_prompt: «## First Scene Emotional Entry Logic» — инструкция выбирать emotional entry moment
  • meta_prompt: «## User Answers Priority for First Scene» — стиль адаптируется к сцене, не наоборот
  • image_suffix: «## FIRST SCENE VISUAL REALISM ADDITIONS»

Ответ: Правило "more aspirational" явно не зафиксировано как отдельное. Аспирациональность достигается через Emotional Authenticity Layer + Identity Refinement Layer.

10. Главный диагноз и приоритеты фиксов

1CRITICAL CODE — Wish pipeline полностью сломан

Проблема: Тип «Уточнение с комментарием» строит FAL prompt = wish_text + image_suffix. Без scene context, без лица, без стиля.

Где: Код prompt builder для generation_type = "comment/wish"

Фикс: Включить в FAL prompt для wish: (1) parent_generation scene_description или parent FAL prompt body, (2) profile_summary, (3) style_resolution_text, (4) Key Answer Locks, (5) original selfie как ip_adapter source (не parent gen output), (6) explicit instruction "change ONLY [wish target], preserve everything else"

2PROMPT — Base Wardrobe материализуется буквально

Проблема: Поле Base Wardrobe в clothing_styles содержит конкретные предметы → LLM читает как инструкцию надеть их, несмотря на правила «интерпретируй как visual direction».

Где: clothing_styles.description_male/female → {chosen_clothing_style} placeholder

Фикс (option A): Переименовать «Base Wardrobe» → «Example items (do not list literally)» и добавить в начало блока стиля: «Это визуальное направление, не список вещей для надевания.»

Фикс (option B): Убрать Base Wardrobe из {chosen_clothing_style} injection, оставить только Visual Code + Identity Feeling + Social Signal + Scene Adaptation.

3DATA — User 7806 выбрал один стиль → невозможность баланса

Проблема: При одном выбранном стиле profile_summary правильно определяет его как dominant, но нет secondary influences → стиль доминирует во всех сценах одинаково.

Где: Onboarding style selection UX

Фикс: Если пользователь выбрал только один стиль → system автоматически добавляет 1-2 compatible secondary influences из preset списка (для Sport Casual: "minimal urban" или "clean natural"). Или показывать подсказку «добавь ещё стиль для разнообразия сцен».

4PROMPT — Профиль 7616 генерируется на английском

Проблема: Character Profile для user 7616 сгенерирован на английском, но инжектируется в русскоязычные meta_prompt-ы.

Где: profile_summary_system prompt — нет явного указания языка вывода

Фикс: Добавить в конец profile_summary_system prompt: «Ответ должен быть строго на русском языке.»
