Авторские календари ELYNE — как реализовать

Документ сшивает концепт Олега (TG 20.06) с вердиктом совета. Главный сдвиг рамки: не вторая афиша, а движок-матч. Публичная механика — не «подписка на автора», а «ELYNE знает тебя → подбирает событие и проводника под того, кем ты становишься». Это единственный ров; всё остальное — Timepad.

1. Принцип, на котором всё держится

Уникальный объект ELYNE — не календарь, а портрет-узнавание по 10 сферам. Значит и авторский слой строим вокруг него:

  • событие хранит не только категорию, но и сферы, которые оно закрывает (Свобода, Род, Творение…);
  • подписка — вторична; первична рекомендация под идентичность: «этот ретрит — для той версии тебя, что хочет Свободу»;
  • курируемая Афиша остаётся чистой: UGC не льётся в общий поток автоматически (защита от шума, который ненавидит человек в кризисе).

Из этого — все ответы на вопросы ТЗ ниже.

2. Поэтапный план (фазовый, не строим платформу впрок)

Фаза 0 — Матч-тест. Неделя 1. Ноль кода.

Проверяем не «нужен ли календарь», а работает ли матч по идентичности и есть ли вообще спрос.

  • Берём 3–5 событий, которые уже лежат в events.json.
  • Руками подбираем под конкретных живых тестеров по их сфере.
  • Отправляем ботом персонально: «это для той версии тебя, что хочет ___».
  • Метрика: тапнул ссылку? дошёл? Если ноль — весь слой бессмысленен, сэкономили полгода.

Фаза 1 — Концьерж supply. Недели 2–3. Минимум кода.

Проверяем сторону авторов, не строя админку.

  • DM 5–10 реальным проводникам: «кинь событие одним сообщением — опубликую бесплатно».
  • Бот собирает карточку через AI-диалог (capability уже есть) → пишет в events.json с новыми полями → деплой существующим скриптом.
  • «Подписка на автора» = тег author_id на событии + кнопка follow в мини-аппе.
  • Уведомление = сообщение от существующего бота.
  • Метрики, которые решают всё: сколько авторов прислали 2-е событие без напоминания; сколько юзеров тапнули «follow author». Ты сам — модератор.

Фаза 2 — Self-serve lite. Только когда поток пошёл.

Строим, когда проводник сам жалуется, что слать в личку медленно.

  • Мини-админка автора внутри Telegram Mini App (не отдельный сайт).
  • Профиль автора, его публичная ссылка (deep-link), редактирование своих событий.
  • Авторизация — через Telegram (уже есть), без отдельных паролей.

Фаза 3 — Платформа и монетизация. После product-market fit.

  • Полные роли, очередь модерации, система уведомлений.
  • Платное/featured попадание в общую афишу.
  • Монетизация: take-rate с билетов, featured-размещение, верификация «проверено ELYNE».

Правило: каждую следующую фазу открываем, только когда метрика предыдущей зелёная. Роли/модерацию/auth/уведомления строим в ответ на реальную боль, а не впрок.

3. Структура данных

Расширяем существующий events.json, добавляем две сущности. На Фазе 1 всё ещё может жить в JSON; БД — с Фазы 2.

event (расширение текущей схемы)

{
  "id": "string",
  "title": "string",
  "date": "2026-06-21",
  "time": "19:00",
  "place": "string | онлайн-ссылка",
  "category": "string",
  "emoji": "🎭",
  "description": "string",
  "url": "string (регистрация)",
  "price": "бесплатно | от 1500 ₽ | донейшн",
  // --- новое ---
  "author_id": "string | null",   // null = кураторская Афиша
  "spheres": ["Свобода", "Творение"], // матч по идентичности
  "source": "curated | author",
  "status": "draft | published | in_afisha", // in_afisha только после модерации
  "cover": "url | null"
}

author

{
  "id": "string",
  "name": "string",
  "tg_user_id": "number",     // авторизация через Telegram
  "bio": "string",            // кто он, что проводит
  "city": "string",           // события локальны — город обязателен
  "categories": ["string"],
  "spheres": ["string"],
  "socials": { "instagram": "url", "telegram": "url" },
  "public_slug": "string",    // для ссылки /author/<slug>
  "verified": false
}

subscription

{
  "user_id": "number",
  "type": "author | category | sphere",
  "target": "string",         // author_id | категория | сфера
  "created_at": "ISO8601"
}

Личная лента юзера — не отдельная таблица, а выборка: события, где author_id ∈ подписки ИЛИ category/sphere ∈ подписки, плюс матч-рекомендации движка по его портрету.

4. Роли (вводим постепенно)

Роль Что может С какой фазы
Пользователь смотреть, подписываться, личная лента Фаза 0
Автор создавать/редактировать свои события, профиль Фаза 1 (концьерж) → 2 (сам)
Модератор пускать UGC в общую афишу, снимать нарушения Фаза 1 = Олег руками, формализуем на 3
Админ ELYNE всё + верификация авторов + монетизация Фаза 3

5. Ответы на конкретные вопросы ТЗ

Q5. Как события автора попадают в общий календарь. Гибрид, чтобы защитить кураторский поток: - в личную ленту подписчиков автора — сразу, автоматически; - в общую Афишу — только после модерации (или платно/featured на Фазе 3). Так UGC не зашумляет курируемое ядро — это прямой риск, который поймал совет.

Q6. Публичная ссылка автора. - MVP: deep-link в Telegram Mini App — t.me/<bot>/app?startapp=author_<slug>. Открывается прямо в ELYNE, без отдельного сайта, авторизация бесплатно. - Красивый elyne.community/author/<name> — позже, как редирект на deep-link (для Instagram-био).

Q7. Максимально простой MVP. Это ровно Фаза 1: автор кидает событие → бот делает карточку → юзер жмёт follow → события автора в его личной ленте. Без ролей, без отдельной админки, без очереди модерации.

6. Сценарии

Автор (Фаза 1): пишет боту «провожу практику в субботу 19:00 на Чистых прудах, донейшн» → бот уточняет недостающее, оформляет в стиле ELYNE, предлагает сферы и категорию → «опубликовать?» → событие в ленте, автор получает свою ссылку для Instagram.

Пользователь: открывает ELYNE → видит не дженерик-список, а «события под тебя» (матч по сферам) + возможность подписаться на автора/категорию → будущие события автора падают в личную ленту → уведомление за день.

Олег-модератор (Фаза 1): новое авторское событие приходит ему в бота → одобряет/правит/пускает в общую Афишу одним тапом.

7. Риски (из разбора совета)

  • Двойной cold-start — нельзя запускать маркетплейс до валидации ядра. Поэтому Фаза 0 не про авторов, а про спрос.
  • Каннибализация Афиши — UGC-шум ломает курируемый актив → жёсткая модерация на входе в общий поток.
  • Гео-фрагментация — событие локально; без города юзер уходит. city обязателен.
  • Юр-хвост — как только авторы продают билеты: возвраты/неявки/ответственность (РФ). До Фазы 3 — только бесплатно/донейшн/внешняя регистрация, деньги не трогаем.
