PROVISIONING.md — Playbook провижининга агента Монад для нового клиента

Owner: monad-tech-architect Версия: 1.0, 2026-06-08 Цель: пошаговое руководство, как поднять копию нашего стека (Монад/Monada) на независимом VPS клиента — от нуля до работающего TG-бота.

Ключевой принцип: клиент владеет всем сам — своим VPS, своими аккаунтами, своими секретами. Мы только конфигурируем. Это и есть «независимость», которую он платит.

1. Что друг делает сам (KYC-привязанное, автоматизировать нельзя)

Всё что ниже — клиент делает лично, своими руками, на свою настоящую личность. Это не баг и не лень с нашей стороны — это стена ToS и KYC, которую легально не перепрыгнуть.

1.1. Аккаунт Anthropic + способ оплаты

Клиент регистрируется на claude.ai на своё имя и телефон. Это необходимо — иначе аккаунт может быть заблокирован по ToS (раздел о третьих лицах, обновление февраль-апрель 2026).

Три варианта оплаты — пусть клиент выбирает по ситуации:

Вариант А: Claude Max-подписка ($100/мес) Это то, что использует Олег. Max даёт 1M-контекст бесплатно (Opus включён), Sonnet для 1M-контекста платный. Клиент платит сам, напрямую claude.ai. Проблема: с РФ-карты не проходит. Решение: Heleket-карта (виртуальная, пополняется USDT через P2P) или попросить платёж через знакомых за рубежом. Подходит для клиентов, которым хочется максимум без счётчика.

Вариант Б: Anthropic API-ключ (pay-per-use) Клиент создаёт API-ключ в console.anthropic.com. Тот же барьер с картой. Решение — та же Heleket-карта. Подходит, если использование умеренное.

Вариант В: Российский шлюз (ProxyAPI или AITUNNEL) — рекомендуем для старта Клиент регистрируется на proxyapi.ru или aitunnel.ru своим email, пополняет баланс рублями с любой РФ-карты. Получает API-ключ. Этот ключ мы вставляем в конфиг вместо anthropic-ключа. Переключается одной строкой: ANTHROPIC_BASE_URL=https://api.proxyapi.ru/v1. Наценка 2-4x к прямому Anthropic, зато полностью без боли для клиента. Подходит для первых запусков.

Почему нельзя автоматизировать: Anthropic явно запрещает регистрацию аккаунтов от лица третьих лиц. КЮ-проверка привязана к личности: при регистрации нужен телефон, иногда карта. Если мы регистрируем “за клиента” — это нарушение ToS; при обнаружении оба аккаунта блокируются.

1.2. Telegram-бот через BotFather

Клиент: 1. Открывает @BotFather в своём TG-аккаунте. 2. Пишет /newbot. 3. Придумывает имя (например «Монад-Васи») и username (например vasya_monad_bot). 4. Получает токен вида 7491234567:AAE... — это и есть TELEGRAM_BOT_TOKEN. 5. Передаёт нам этот токен.

Почему нельзя автоматизировать: BotFather работает только через живой TG-аккаунт с телефонной верификацией. Автосоздание ботов программно — не предусмотрено и нарушает ToS Telegram.

1.3. GitHub-аккаунт + приватное репо

Клиент регистрируется на github.com (достаточно бесплатного плана). Мы создаём там приватное репо (называем например моняbot или что нравится), инвайтим клиента как owner. Репо будет хранить конфиги, vault, скрипты — но не секреты (они шифруются через age).

Если клиент не хочет возиться с GitHub вообще — можно обойтись без него на первом этапе. Но тогда нет версионирования, rollback при ошибке сложнее.

Почему нельзя автоматизировать: GitHub требует верификацию email + телефона для приватных репо. Автоматическая регистрация через скрипты нарушает GitHub Terms of Service (раздел о массовой регистрации аккаунтов).

1.4. Google-аккаунт + OAuth (если нужен Google Workspace MCP)

Если клиент хочет интеграцию с Gmail/Google Calendar/Drive — он должен сам: 1. Выдать нам OAuth-согласие через стандартный Google flow (мы присылаем ссылку, он кликает, разрешает). 2. Результат — refresh_token, который мы кладём в зашифрованный .env.age.

Без этого Google MCP не подключается. Если клиент не нужен Google Workspace — можно пропустить.

1.5. VPS: клиент берёт сам или мы берём на него

Два варианта: - Клиент сам регистрируется у провайдера и оплачивает — сервер в его полной собственности. - Мы берём под него (на нашу карту), но тогда у нас есть root и клиент зависит от нас — это противоречит концепции «независимости».

Рекомендация для первых тестов: клиент оплачивает сам, мы помогаем выбрать тариф. Провайдеры — см. раздел 5.

2. Что поднимаем мы (пошаговый провижининг)

Предполагается: VPS получен, Ubuntu 22.04 или 24.04 установлена, есть root-доступ по SSH. Клиент передал нам: TG-токен бота, API-ключ (Anthropic или шлюз), свой TG user_id (его можно узнать через @userinfobot).

2.1. Базовые зависимости сервера

apt update && apt upgrade -y
apt install -y git curl wget jq age unzip python3 python3-pip yamllint sqlite3 shred

[СКРИПТУЕТСЯ] — войдёт в bootstrap-скрипт.

Node.js 20.x:

curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
apt install -y nodejs

[СКРИПТУЕТСЯ]

Bun (нужен для ClaudeClaw — это его runtime):

curl -fsSL https://bun.sh/install | bash
# После этого bun доступен в ~/.bun/bin/bun

[СКРИПТУЕТСЯ]

pipx + Python-пакеты:

pip3 install pipx
pipx ensurepath
pipx install mempalace

[СКРИПТУЕТСЯ]

Playwright (для MCP-сервера playwright):

npx playwright install --with-deps chromium

[СКРИПТУЕТСЯ] — долго, ~5 минут, устанавливает браузер.

2.2. Установка Claude Code CLI

npm install -g @anthropic-ai/claude-code

[СКРИПТУЕТСЯ]

После установки — первая авторизация. Здесь есть нюанс: - Если клиент использует Max-подписку: claude при первом запуске откроет браузерный OAuth — клиент логинится сам в своём браузере. Это единственный ручной шаг авторизации. - Если клиент использует API-ключ: прописываем ANTHROPIC_API_KEY в .env.age и ANTHROPIC_BASE_URL (если через шлюз) — браузер не нужен.

[РУЧНОЙ] — первая авторизация OAuth для Max, клиент должен быть рядом с браузером.

2.3. Клонирование репозитория

git clone git@github.com:USERNAME/REPONAME.git ~/Monada
cd ~/Monada

Репо — либо форк нашего шаблонного, либо свежий клон с подготовленной структурой. [СКРИПТУЕТСЯ]

2.4. Генерация age-ключей (шифрование секретов)

mkdir -p ~/.config/age
age-keygen -o ~/.config/age/key.txt
# Публичный ключ сохраняем отдельно для шифрования
grep "^# public key:" ~/.config/age/key.txt | cut -d' ' -f4 > ~/.config/age/recipient.pub

[СКРИПТУЕТСЯ]

Приватный ключ ~/.config/age/key.txt — нигде не хранится кроме сервера. Если потерян — секреты недоступны. Нужно сделать резервную копию в безопасное место (клиент сам хранит, например в Bitwarden).

2.5. Заливка секретов через add-secret.sh

Для каждого секрета:

bash ~/Monada/bin/add-secret.sh TELEGRAM_BOT_TOKEN=<токен>
bash ~/Monada/bin/add-secret.sh ANTHROPIC_API_KEY=<ключ>
bash ~/Monada/bin/add-secret.sh ANTHROPIC_BASE_URL=<если через шлюз>
# Опционально:
bash ~/Monada/bin/add-secret.sh FAL_KEY=<ключ fal.ai>
bash ~/Monada/bin/add-secret.sh GOOGLE_REFRESH_TOKEN=<токен>

[УЖЕ ЕСТЬ СКРИПТ bin/add-secret.sh] — скрипт сам шифрует через age и коммитит в репо.

2.6. Настройка ClaudeClaw (settings.json)

ClaudeClaw — Telegram-демон, который слушает входящие сообщения и спавнит claude -p на каждый. Его конфиг живёт в .claude/claudeclaw/settings.json.

Что нужно заполнить под клиента:

{
  "model": "opus",
  "telegram": {
    "token": "<TELEGRAM_BOT_TOKEN>",
    "allowedUserIds": [<TG_USER_ID_клиента>],
    "listenGroupIds": []
  },
  "security": {
    "level": "unrestricted"
  },
  "web": {
    "enabled": true,
    "host": "127.0.0.1",
    "port": 3141
  }
}

[СКРИПТУЕТСЯ] — jq-команда заполняет этот файл из переменных.

Важно про модель: если клиент на Max-подписке — ставим "model": "opus" (Opus 4 в Max бесплатен). Если на API-ключе или шлюзе — рекомендуем "model": "sonnet" (Sonnet дешевле в 5 раз, для обычных задач хватает). Подробнее — в reseller-research.

2.7. Установка ClaudeClaw как плагина

ClaudeClaw устанавливается как Claude Code Plugin:

claude plugins install claudeclaw

После установки появляется в ~/.claude/plugins/cache/claudeclaw/.

[СКРИПТУЕТСЯ] — одна команда.

2.8. Настройка MCP-серверов (.mcp.json)

Файл .mcp.json в корне репо определяет, какие MCP-серверы доступны агенту. Для нового клиента — копируем наш шаблон и правим пути.

Обязательные пути под нового пользователя (все /home/oleg/ → /home/USERNAME/):

{
  "mcpServers": {
    "mempalace": {
      "type": "stdio",
      "command": "/home/USERNAME/.local/pipx/venvs/mempalace/bin/python",
      "args": ["-m", "mempalace.mcp_server", "--palace", "/home/USERNAME/Monada/memory"]
    },
    "web-search": {
      "type": "stdio",
      "command": "node",
      "args": ["/home/USERNAME/mcp-servers/web-search-mcp/dist/index.js"],
      "env": {"BROWSER_HEADLESS": "true", "MAX_BROWSERS": "2"}
    },
    "playwright": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@playwright/mcp@0.0.70"]
    },
    "telegram-mcp": {
      "type": "stdio",
      "command": "/home/USERNAME/Monada/bin/telegram-mcp-wrapper.sh"
    }
  }
}

[СКРИПТУЕТСЯ] — sed -i заменяет /home/oleg/ на /home/USERNAME/ по всем файлам.

2.9. Настройка personas и CLAUDE.md

Создаём персональный файл агента для клиента. Берём .claude/personas/boris.md как шаблон, меняем: - Имя агента (например «Максим», «Иван» — как клиент хочет называть своего бота) - Имя владельца («Олег» → «Вася») - Часовой пояс в config.yaml

[РУЧНОЙ] — выбор имени и деталей персонажа лучше обсудить с клиентом. Занимает 10-15 минут.

2.10. Настройка systemd-сервисов

Создаём юнит для автозапуска:

# ~/.config/systemd/user/claude-code.service
[Unit]
Description=ClaudeClaw daemon for <NAME>-bot
After=network-online.target
Wants=network-online.target
StartLimitBurst=5
StartLimitIntervalSec=600

[Service]
Type=simple
ExecStart=/home/USERNAME/Monada/bin/start.sh
Restart=on-failure
RestartSec=10
KillMode=mixed
TimeoutStopSec=15
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=default.target

systemctl --user daemon-reload
systemctl --user enable claude-code.service
systemctl --user start claude-code.service
# Чтобы user-сервисы стартовали без входа:
loginctl enable-linger USERNAME

[СКРИПТУЕТСЯ]

2.11. Настройка crontab (мониторинг и watchdog)

# Heartbeat — трогаем файл каждые 15 мин (watchdog следит за ним)
*/15 * * * * /home/USERNAME/Monada/bin/heartbeat-touch.sh >/dev/null 2>&1
# Мониторинг размера jsonl-файла сессии (защита от bloat и OOM)
*/10 * * * * /home/USERNAME/Monada/bin/jsonl-size-monitor.sh >> /home/USERNAME/Monada/.claude/claudeclaw/logs/jsonl-monitor.log 2>&1
# Архивирование jsonl раз в сутки в 4:15
15 4 * * * /home/USERNAME/Monada/bin/jsonl-archive.sh >> /home/USERNAME/Monada/.claude/claudeclaw/logs/jsonl-archive.log 2>&1
# Watchdog: если агент завис больше 45 мин — авторестарт
* * * * * /home/USERNAME/Monada/bin/claude-hang-watchdog.sh >/dev/null 2>&1
# Мониторинг диска 4 раза в сутки
23 0,6,12,18 * * * /home/USERNAME/Monada/bin/disk-monitor.sh >> /home/USERNAME/Monada/.claude/claudeclaw/logs/disk-monitor.log 2>&1

[СКРИПТУЕТСЯ] — добавляется через crontab -l | cat - new_lines | crontab -.

2.12. Проверка живости (canary-тест)

После старта: 1. Агент при первом запуске присылает сообщение в TG с кодом CANARY-XXXXXXXX. 2. Клиент видит сообщение — агент жив. 3. Отправляем тестовый вопрос боту: «Привет, ты кто?» — должен ответить по персоне.

[РУЧНОЙ] — нельзя автоматизировать, нужен живой человек с TG.

3. Bootstrap-скрипт: концепция

Единый bootstrap-agent.sh — запускается на свежем VPS от root, делает шаги 2.1–2.11 в одну команду.

Что принимает на вход (флаги или интерактивный ввод):

bash bootstrap-agent.sh \
  --username vasya \
  --agent-name "Монад-Васи" \
  --tg-token "7491234567:AAE..." \
  --tg-user-id "123456789" \
  --anthropic-key "sk-ant-..." \
  --anthropic-base-url "https://api.proxyapi.ru/v1" \
  --repo-url "git@github.com:vasya/monadbot.git" \
  --timezone "Europe/Moscow"

Опциональные параметры (могут добавляться позже через add-secret.sh): - --fal-key — для генерации изображений - --google-refresh-token — для Google Workspace MCP

Структура скрипта (псевдокод):

#!/bin/bash
# bootstrap-agent.sh
set -euo pipefail

# 0. Парсинг аргументов (или интерактивный ввод если не переданы)
parse_args "$@"
confirm_summary           # Показать сводку: "Создаю агента X для @Y, шлюз Z. OK?"

# 1. Создание пользователя (если нужен отдельный unix-user)
create_unix_user "$USERNAME"
loginctl enable-linger "$USERNAME"

# 2. Установка системных пакетов
install_system_deps       # apt: git curl wget jq age sqlite3 yamllint ...

# 3. Node.js 20 + Bun
install_nodejs
install_bun

# 4. Python + pipx + mempalace
install_python_deps

# 5. Playwright браузер
install_playwright

# 6. Claude Code CLI
npm install -g @anthropic-ai/claude-code

# 7. Клонирование шаблонного репо
clone_repo "$REPO_URL" "/home/$USERNAME/Monada"

# 8. Генерация age-ключей
generate_age_keys "/home/$USERNAME"

# 9. Заливка секретов
add_secret TELEGRAM_BOT_TOKEN "$TG_TOKEN"
add_secret ANTHROPIC_API_KEY "$ANTHROPIC_KEY"
[[ -n "$ANTHROPIC_BASE_URL" ]] && add_secret ANTHROPIC_BASE_URL "$ANTHROPIC_BASE_URL"

# 10. Настройка ClaudeClaw settings.json
patch_claudeclaw_settings "$TG_TOKEN" "$TG_USER_ID"

# 11. Настройка .mcp.json (замена путей)
patch_mcp_paths "$USERNAME"

# 12. Настройка config.yaml (timezone, agent name)
patch_config "$TIMEZONE" "$AGENT_NAME"

# 13. Установка ClaudeClaw плагина
su -c "claude plugins install claudeclaw" "$USERNAME"

# 14. Установка MCP web-search сервера
install_web_search_mcp "/home/$USERNAME"

# 15. systemd-юнит
install_systemd_unit "$USERNAME"

# 16. Crontab
install_crontab "$USERNAME"

# 17. Первый старт
systemctl --user start claude-code.service

echo "=========================================="
echo "Bootstrap завершён. Проверь TG — бот должен написать CANARY-код."
echo "Если не написал в течение 60 секунд — смотри логи:"
echo "  journalctl --user -u claude-code.service -n 50"
echo "=========================================="

Что скрипт НЕ может сделать:

  • Войти в claude.ai OAuth (нужен браузер клиента для Max-подписки).
  • Создать TG-бота в BotFather.
  • Зарегистрировать аккаунт в Anthropic/ProxyAPI/GitHub от имени клиента.
  • Выдать Google OAuth-согласие.

Эти 4 шага всегда остаются ручными — это жёсткая стена KYC/ToS.

5. Хостинг: требования к VPS

Минимальные требования

Ресурс Минимум Рекомендуется Почему
RAM 2 GB 4 GB Claude Code + Bun + MCP-серверы в сумме потребляют ~800 MB в покое. При обработке больших контекстов (1M токенов) может уходить до 1.5-2 GB. На 2 GB будет swap, на 4 GB — свободно.
CPU 1 vCPU 2 vCPU Агент не CPU-интенсивен. 1 vCPU достаточно, но при параллельных задачах (несколько MCP одновременно) — 2 лучше.
Диск 20 GB SSD 40 GB SSD MemPalace база растёт, Playwright браузер занимает ~500 MB, vault/logs — ещё накапливается. У Олега на 30 GB уже 97% занято.
ОС Ubuntu 22.04 Ubuntu 22.04 LTS Проверено. 24.04 должна работать, не тестировалось. Никаких контейнеров типа OpenVZ — нужен полноценный Linux (systemd, loginctl).
Сеть Без РФ-блокировок Без РФ-блокировок Агент обращается к api.anthropic.com (или шлюзу), api.telegram.org, github.com. Провайдеры внутри РФ иногда блокируют Telegram-API на уровне DPI. Лучше брать VPS за рубежом или у провайдера без этих проблем.

Важная заметка про «веб-хостинг»

Обычный «веб-хостинг» (типа того что Олег называет «изхостинг» или «timeweb-подобный») для этого не подойдёт. Причины: - Нет доступа по SSH как root. - Нет systemd (только Apache/Nginx для сайтов). - Нет возможности запустить фоновые демоны. - Нет полного Linux-окружения.

Нужен именно VPS (виртуальный частный сервер) с KVM-виртуализацией и полным Ubuntu. Это другая категория услуги — обычно от 300-600 руб/мес за минимальный тариф.

Варианты провайдеров (требования, не реклама)

Ориентиры по критериям — хорошая сеть за рубежом без блокировок + принимают РФ-карты:

  1. Timeweb Cloud VPS — российский провайдер, принимает рублёвые карты, есть KVM, Ubuntu 22.04. Вопрос — нет ли ограничений на исходящие к Telegram/Anthropic. Нужно проверить перед покупкой.

  2. Selectel VPS — ещё один российский с KVM, хорошая репутация среди разработчиков. Аналогичный вопрос про блокировки.

  3. Hetzner (Германия) / DigitalOcean / Vultr — зарубежные провайдеры, никаких блокировок, отличная сеть. Не принимают РФ-карты напрямую, но через Heleket-карту (USDT) или карту родственников за рубежом — работают. Цена стартует от ~€5/мес (3-4 GB RAM, 40 GB диск).

Итоговая рекомендация: если есть возможность оплатить зарубежный VPS (Hetzner CX22 или аналог, €5-7/мес) — берём его. Если только рублёвая карта — Timeweb Cloud или Selectel, но сначала убедиться что Telegram API доступен.

6. Дорожная карта автоматизации

Этап 1: Manual (сейчас, первый друг)

Режим: Олег сидит рядом и делает по этому чеклисту.

Что ручное: - Все KYC-шаги клиента (TG-бот, аккаунты, OAuth) - Настройка персоны и имени агента - Первая авторизация claude OAuth - Canary-проверка

Что автоматизировано уже сейчас: - add-secret.sh — шифрует и коммитит секреты - apply-config.sh, apply-settings.sh — патчат конфиг с рестартом и канарейкой - session-start хуки, watchdog, cron — из коробки после настройки

Примерное время провижининга вручную: 2-4 часа (основное время — ожидание установок и разбор непоняток).

Этап 2: Semi-auto (после первого друга)

Цель: написан bootstrap-agent.sh (см. раздел 3), проверен на реальном VPS.

Что остаётся ручным (KYC-стена): - Все 4 пункта раздела 1 — клиент делает сам, никак не автоматизируется.

Что переходит в автомат: - Установка всех зависимостей одной командой. - Клонирование + патч путей + заливка секретов. - systemd + crontab.

Примерное время: 30-40 минут (из них 20 мин — ожидание установки Playwright).

Этап 3: Near-auto (горизонт)

Технически реализуемо дополнительно: - Веб-форма (или TG-бот для нас) куда клиент вводит TG-токен, API-ключ, TG user_id — и мы запускаем bootstrap по SSH автоматически. - Шаблонное репо с GitHub Template Repository — один клик, клиент получает свой форк. - Автопровижининг VPS через API провайдера (Hetzner/DO API) — если клиент оплачивает у них по карте, мы деплоим к ним скриптом.

Жёсткая стена, которую не перейти: - Авторизация claude OAuth для Max-подписки — браузер клиента, обойти нельзя. - Создание TG-бота — только через BotFather лично. - Регистрация аккаунтов Anthropic/GitHub/Google от лица клиента — прямо запрещено ToS всех трёх сервисов. - Настройка персоны — технически можно автоматизировать, но результат будет хуже чем 15 минут живого разговора с клиентом.

Честный предел автоматизации: ~85-90% работы автоматизируется. Оставшиеся 10-15% — это KYC и первый контакт с клиентом, и это правильно: именно эти шаги дают клиенту ощущение что это ЕГО ассистент, не наш.

7. ToS и KYC-риски

Кратко — подробности в research/tech/2026-04-26-anthropic-reseller-pathways.md.

Главное правило: каждый клиент владеет своими аккаунтами и платит своей картой. Мы — инсталляторы и технические помощники, не посредники в перепродаже API.

Конкретные риски:

Риск Статус Митигейшн
Anthropic: регистрация аккаунтов от лица третьих лиц Прямо запрещено ToS (раздел о третьих лицах) Не делаем. Клиент регистрируется сам.
Anthropic: один master-key для нескольких клиентов Серая зона (wrapper-SaaS) Каждый клиент = свой API-ключ в своём аккаунте
GitHub: массовая автоматическая регистрация Запрещено ToS Не делаем.
Google: OAuth от чужого имени Технически невозможно без фишинга, запрещено Стандартный OAuth-flow, клиент сам кликает согласие
Telegram: автосоздание ботов Не поддерживается API BotFather Клиент сам создаёт через @BotFather
VPS-провайдер (зарубежный): санкции РФ Реальный риск (Hetzner, DO) Клиент оплачивает сам, данные на его аккаунте; при риске — переезд на другой VPS за 1-2 дня

Открытые вопросы к Олегу

Перед первым провижинингом нужны ответы:

  1. Имя агента для друга. Это будет «Монад-Коля» / «персональный Монад» / что-то своё? Это влияет на то, что мы пишем в persona-файл. Лучше обсудить с другом лично — это его ассистент.

  2. Модель: Max-подписка или шлюз? Если друг готов разобраться с Heleket-картой и USDT — Max ($100/мес, без счётчика) удобнее. Если хочет минимальный порог входа — ProxyAPI (рубли, но дороже на токен). Это нужно решить до провижининга, потому что меняет шаг авторизации.

  3. Нужен ли Google Workspace MCP? Если да — другу придётся выдавать OAuth-согласие во время провижининга. Если нет (не пользуется Google Calendar/Gmail) — пропускаем, добавим позже.

  4. Хостинг: кто берёт VPS? Друг сам регистрируется у провайдера и оплачивает, или Олег оплачивает за него? Первый вариант правильнее для концепции «независимости» и чище по ответственности. Но надо понять, готов ли друг разобраться с провайдером сам (там 10-15 минут, не сложно).

  5. Какие фичи из опциональных реально нужны на старте? fal-ai (генерация картинок), playwright (браузер), Google Workspace — каждый добавляет +5-10 минут к провижинингу и требует отдельного API-ключа. Рекомендую на первом запуске ограничиться core-набором: TG-бот + память + веб-поиск. Остальное — по запросу.
